# 整理来源与排除范围

## 来源

| 来源 | 审阅稿位置 | 处理 |
| --- | --- | --- |
| 原GitHub仓库 main | `offline-preservation`；根 `LICENSE` | 基于提交 `6e2c4e9`，保留62个原文件的内容与Git历史 |
| 本机在线工程 | `online` | 选择源码、测试、静态页面、小型目录数据和必要构建工具 |
| 恢复工程的本地模式客户端 | `local-mode` | 整合Java桥接及双区服构建/补丁工具 |
| 在线工程的独立活动服务源码 | `experiments/activity` | 保留数据与影子实现，不复制安装包、存档和日志 |
| 未发布石板草稿 | `experiments/stone-slate` | 保留Java、相关测试和接入稳定源码所需的差异补丁 |

`source-manifest.json` 记录每个复制文件的来源组、相对来源路径、原始SHA-256与整理稿SHA-256。没有记录私钥、账号存档路径或凭据内容。

已有构建输入和源码有字节级哈希约束，`.gitattributes` 对导入的 `online`、`local-mode`、`experiments` 保留原UTF-8字节，不自动变更换行。原单机保留其自身属性；清单另记规范换行的校验值，兼容不同系统检出文本时的行尾差异。

## 为何保留部分历史脚本

Android构建工具互相导入，也会将Java源码转换后编译；按旧版号或 `probe` 字样直接删文件会破坏依赖。本稿按组件保留这些源码，并在组件README中标明它们不是统一的当前构建入口。

稳定Java服务使用 `Build.ps1`。按特定旧JAR编译少量类的工具仅保留供追溯，不能直接在稳定源码副本中按原步骤运行：石板接线已剥离，部分工具会检查旧源码形状和二进制哈希。

## 未复制的文件

- `.local`、身份凭据、证书与签名私钥。
- 玩家存档、账号数据库、服务状态、真实邮件验证记录。
- 正式发布、数据补偿、账号重置、远程部署的一次性运营脚本。
- 构建目录、缓存、APK/JAR/DEX成品、更新发布目录。
- 验收日志、截图、录屏、重复资源与头像原图。
- Unity工程大型资源和原始资料包；现有本机文件未移动或删除。

## 有目的的例外

`preserved_battle_catalog.json` 原来放在测试资料目录，但它是当前有效布局输入，不是玩家数据。因此复制到稳定服务 `resources`，并核对其字节与现有本地服务内资源一致。

`offline_responses.json` 名称虽含 offline，实际是只读原协议模板与定义表，不能按名字当作玩家存档删除。

源配置中的原游戏文字、参数、ID以及已生成布局仍受原始内容的权利归属限制，见根 [NOTICE](../NOTICE.md)。
