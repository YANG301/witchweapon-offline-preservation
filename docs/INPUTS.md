# 外部输入与资料

## 已放进审阅稿的内容

- 原单机保存工程的源码和原仓库自带的基础响应数据。
- 在线版 Java 原协议响应模板及其 `_catalog`，用于服务端物品、魔女、兵器等定义。
- 主线、日常、熔炉、商店、任务、回收和迷宫的已生成 JSON。
- 已恢复的战斗布局目录 `preserved_battle_catalog.json`：247 个已具备布局的关卡，另列50个缺失关卡。
- Go 管理后台嵌入用的页面、脚本和物品名称表。
- 玩家公告的各版简要更新记录，以及用户协议文本。

这些是程序输入或配置，不是玩家运行存档。来源与哈希在 [来源清单](source-manifest.json) 中。

## 没有放进源码稿的内容

| 内容 | 原因与使用方式 |
| --- | --- |
| 原 Android APK、PC 保存版程序、完整资源包 | 构建或提取时由维护者提供，原单机所需输入哈希见其 `INPUTS.md` |
| 历代整合 APK、验收候选 JAR 和 DEX | 属于固定构建输入或产物，保留在现有工程中；不伪装成源码依赖 |
| 热更新 blobs、签名清单与发布目录 | 属于发布产物；签名服务源码保留 |
| APK 签名私钥、热更新私钥、Cloudflare 令牌、VPS 凭据 | 仅本机私密配置使用；不会随源码复制 |
| 玩家存档、账号库、邮箱验证记录、运营恢复记录 | 实际服务数据，未加入审阅稿 |
| 感谢头像、截图、录屏、群聊资料 | 外部展示素材，未复制到源码仓库 |
| Unity 工程和提取资源的大型二进制 | 现有 D 盘恢复项目继续保留，本稿只收录相关代码与小型配置 |

## 安卓 v125 构建链仍需的输入

`online/android-client/build_startup_version_v125_apk.py` 仍按历史构建锁定以下内容：

1. v124 整合 APK 及脚本指定的 SHA-256。
2. 第191版完整签名资源清单和所有覆盖资源。
3. 原公告资源整合记录，用于取得对应的 `release` 信息。
4. 维护者的 APK 签名环境、公钥及相应原始工具输入。
5. `local-mode` 的双区服构建和桥接脚本。

当前保留的历史脚本使用了原工程的绝对路径，部分工具还依赖前一版候选 APK。新克隆机器应先完成路径和输入参数化，不能把这些脚本视作无资料的一键构建。

## 尚缺的战斗资料

50 个关卡 ID 在 `preserved_battle_catalog.json` 的 `missingStageIds` 中保留：普通第14、15、16章各15关，以及困难关卡 `3120001007`、`3120002007`、`3120003007`、`3120004007`、`3120007005`。

已有布局并不代表所有武器、技能、Buff、召唤与掉率都取得完整原服资料。未公开的细项采用恢复规则或用户确定的数值时，应继续保留来源说明，不宣称已经完整复原原服务器。
